# Render Deployment Guide: TogetherSpace

This guide covers how to deploy the **TogetherSpace** backend (and frontend) to Render.

---

## Method 1: Deploy with Render Blueprint (Recommended - 1 Click)

1. Log in to [Render Dashboard](https://dashboard.render.com).
2. Click **Blueprints** in the top navigation.
3. Click **New Blueprint Instance**.
4. Connect your GitHub repository (`Ujjawal0001/chat-app`).
5. Render will automatically detect [`render.yaml`](./render.yaml).
6. Fill in the required environment variables:
   - `DATABASE_URL`: Your Supabase or PostgreSQL connection string (Transaction pooler on port 6543).
   - `DIRECT_URL`: Direct PostgreSQL connection string (Port 5432).
   - `FRONTEND_URL`: Your deployed frontend URL (e.g., `https://your-app.vercel.app` or `https://togetherspace-frontend.onrender.com`).
   - `INITIAL_SETUP_SECRET`: A secure passphrase you choose to unlock the initial owner setup.
   - `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`: From your Cloudinary dashboard.
   - `JWT_SECRET`: Auto-generated by Render.
7. Click **Apply**. Render will automatically build, run migrations, and launch your API service!

---

## Method 2: Manual Web Service Setup (Backend on Render)

If you prefer setting up the Web Service manually:

1. In Render Dashboard, click **New +** > **Web Service**.
2. Select your repository `chat-app`.
3. Configure the settings:
   - **Name**: `togetherspace-api`
   - **Region**: Oregon (or your preferred region)
   - **Branch**: `main`
   - **Root Directory**: `backend`
   - **Runtime**: `Node`
   - **Build Command**: `npm install && npx prisma generate`
   - **Start Command**: `node src/server.js`
   - **Plan**: Free (or Starter)
4. Under **Advanced**:
   - **Health Check Path**: `/api/health`
   - **Auto-Deploy**: Yes
5. Under **Environment Variables**, add:
   | Key | Value / Notes |
   |---|---|
   | `NODE_ENV` | `production` |
   | `PORT` | `10000` |
   | `FRONTEND_URL` | Your frontend domain (e.g. `https://your-frontend.vercel.app`) |
   | `DATABASE_URL` | Your PostgreSQL pooled connection string |
   | `DIRECT_URL` | Your PostgreSQL direct connection string |
   | `JWT_SECRET` | 32+ character random string |
   | `INITIAL_SETUP_SECRET` | Custom passphrase for initial setup |
   | `CLOUDINARY_CLOUD_NAME` | Cloudinary Cloud Name |
   | `CLOUDINARY_API_KEY` | Cloudinary API Key |
   | `CLOUDINARY_API_SECRET` | Cloudinary API Secret |
   | `CLOUDINARY_FOLDER` | `togetherspace` |
   | `MAX_IMAGE_FILE_SIZE` | `20971520` |
   | `MAX_VIDEO_FILE_SIZE` | `104857600` |
6. Click **Create Web Service**.

## Important Render Considerations Handled in Code

1. **Proxy Trust**: `app.set('trust proxy', 1)` is enabled in `backend/src/app.js` so Render's SSL-terminating reverse proxy forwards the correct client IP and protocol headers.
2. **Cross-Site Cookies**: For decoupled hosting (e.g. Frontend on Vercel and Backend on Render), authentication cookies are configured with `SameSite=None` and `Secure=true`.
3. **Health Check**: Render pings `/api/health` during deploys to guarantee zero-downtime rolling updates.
4. **CORS Flexibility**: Configured to cleanly strip trailing slashes and dynamically allow your configured `FRONTEND_URL`, `.vercel.app`, and `.onrender.com` domains.
